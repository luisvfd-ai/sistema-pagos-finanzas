Cómo usar esta sección

Esta página no reemplaza una capacitación formal, pero sí funciona como guía rápida para resolver dudas habituales dentro de la app y mantener una operación consistente.

Recomendación general: para el trabajo diario, el flujo principal suele ser: Dashboard → Alertas → Cuentas por pagar → Registrar pago → Reportes.
Novedades ya integradas: el sistema ahora soporta compromisos en cuotas, compromisos únicos, gastos recurrentes mensuales, selección múltiple con exportación de seleccionados en cuentas por pagar, categorías recurrentes parametrizables, módulo de auditoría, filtro por tipo de deuda en reportes, reportes rápidos y exportación de proyección futura en CSV, Excel y PDF.
Importante: el sistema no está pensado solo para registrar pagos. Está diseñado para representar la realidad financiera operativa de la empresa: compromisos, eventos futuros, pagos reales, saldo pendiente, proyección y riesgo.

Qué hace realmente el sistema

  • PagoProgramado: representa el compromiso financiero base.
  • EventoPago: representa los eventos o cuotas futuras generadas desde ese compromiso.
  • PagoReal: representa lo que efectivamente se pagó, incluyendo abonos parciales.
  • La lectura financiera principal ya no se hace solo sobre la deuda base, sino sobre la combinación entre eventos y pagos reales.
  • Por eso el sistema puede mostrar saldo pendiente real, flujo futuro, riesgo y avance operativo por compromiso.
Idea clave: un compromiso puede existir, tener eventos pendientes y además pagos reales parciales. El sistema está pensado para reflejar exactamente esa realidad operativa.

Flujo recomendado de uso

  1. Revisar Dashboard para entender el estado general.
  2. Entrar a Alertas para priorizar vencidos y próximos vencimientos.
  3. Trabajar el detalle en Cuentas por pagar usando filtros, selección y acciones por fila.
  4. Registrar Pago real o abono cuando la empresa efectivamente pague.
  5. Consultar Reportes usando filtros avanzados o reportes rápidos según la pregunta que quieres responder.
  6. Exportar histórico o proyección cuando necesites priorizar, compartir o preparar tesorería.
  7. Usar Auditoría cuando sea necesario revisar trazabilidad de cambios o movimientos.

Dashboard

  • Entrega una visión ejecutiva del estado financiero actual.
  • Resume KPIs principales, riesgo, compromisos vencidos, próximos eventos, proyección y lecturas agregadas.
  • Incluye resumen por unidad, gastos recurrentes por categoría y lectura cruzada unidad / categoría.
  • No reemplaza la gestión detallada: para trabajar compromiso por compromiso, la pantalla principal sigue siendo Cuentas por pagar.
  • Los compromisos inactivos o anulados no deben entrar en la lectura operativa principal.

Alertas

  • Muestra compromisos vencidos, de hoy y próximos según urgencia operativa.
  • Su objetivo es priorizar la acción, no reemplazar el análisis histórico.
  • Cuando existe pago parcial o abono, lo importante es el saldo pendiente real o el saldo visible del período.
  • Desde esta vista se detectan rápidamente obligaciones críticas que requieren gestión inmediata.
  • Los compromisos anulados o inactivos no deben aparecer como urgencia operativa.

Cuentas por pagar

  • Es la herramienta principal de gestión operativa del sistema.
  • Permite filtrar por búsqueda, unidad, tipo, categoría recurrente, estado, activo y ver pagados.
  • La vista puede exportarse a Excel, CSV y PDF, respetando exactamente los filtros aplicados.
  • Incluye selección múltiple con checkbox por fila, selección de visibles, limpieza de selección, sumatoria y exportación solo de seleccionados.
  • En compromisos en cuotas, la tabla se centra en la cuota operativa actual, el abonado de esa cuota, el saldo cuota y el saldo visible.
  • En gastos recurrentes, la tabla muestra el saldo visible del mes y la proyección del horizonte como referencia adicional.
  • La barra de progreso representa el avance operativo del compromiso y se apoya en el porcentaje mostrado.
  • Desde esta pantalla se puede editar, registrar abonos, anular y, cuando corresponde, eliminar definitivamente.
Consejo práctico: si necesitas trabajar una deuda específica, esta es la vista correcta. Usa Dashboard para ver y Cuentas por pagar para operar.

Modos de programación

  • En cuotas: para créditos, compras en cuotas, cheques a fecha o compromisos con una cantidad finita de vencimientos.
  • Único: para un solo pago puntual. El sistema lo normaliza como un único evento.
  • Recurrente mensual: para gastos operativos que se repiten mes a mes, como sueldos, arriendos y servicios.
Regla práctica: si un gasto se repite todos los meses, no debería cargarse como deuda en cuotas. Lo correcto es usar recurrente mensual.

Gastos recurrentes

  • Se usan para sueldos, arriendos, agua, luz, internet, gas, gastos comunes, servicios y honorarios.
  • Se crean una sola vez y luego el sistema genera eventos futuros mensuales dentro del horizonte operativo.
  • El monto base sirve para proyectar; el pago real del mes se registra aparte cuando se paga efectivamente.
  • El recurrente puede ser indefinido o tener fecha fin.
  • La categoría recurrente mejora la lectura del dashboard, reportes y cuentas por pagar.
  • El sistema usa una lógica segura de transición entre el campo legado y categoria_recurrente_ref, evitando romper datos históricos.
Ejemplo correcto: crear “Sueldo Natasha” como recurrente mensual y luego registrar el pago real de abril cuando se pague. Así mantienes proyección futura e historial real.

Registrar pago / abono

  • Sirve para registrar pagos reales completos y también abonos parciales.
  • Un compromiso no se considera totalmente resuelto hasta que el saldo real o el saldo visible del período quede en cero.
  • Registrar un abono no borra el compromiso base: ajusta la lectura operativa y conserva el historial de lo pagado.
  • En recurrentes, el pago real debe asociarse al compromiso recurrente correspondiente.
  • El sistema distingue entre saldo total estructural y saldo visible operativo, especialmente en compromisos únicos y recurrentes.
  • Los pagos reales son parte clave de la lógica financiera, porque permiten conciliar eventos y calcular cuánto se ha pagado realmente.

Reportes

  • Permiten analizar pagos reales por período usando filtro de fechas.
  • Soportan filtro por unidad de negocio, categoría recurrente y tipo de deuda.
  • El bloque histórico trabaja sobre pagos reales; la proyección futura trabaja sobre eventos pendientes.
  • La proyección futura ya respeta el rango del reporte: considera el tramo entre la fecha desde seleccionada y la fecha hasta, sin retroceder antes de hoy.
  • Incluyen exportación histórica a CSV, Excel y PDF, y también exportación propia de la proyección futura en esos mismos formatos.
  • Incorporan análisis de recurrentes, desglose por unidad o categoría y lectura por tipo de obligación.
  • Ahora incluyen Reportes rápidos, pensados para responder preguntas frecuentes sin tener que construir todos los filtros manualmente.
Reportes rápidos actualmente disponibles: pagos reales del período, unidad con mayor salida, proyección priorizada, créditos y obligaciones financieras, recurrentes por categoría y calendario futuro.

Unidades y categorías recurrentes

  • Unidades de negocio ya son parametrizables y se usan transversalmente en dashboard, reportes y cuentas por pagar.
  • Categorías recurrentes también son parametrizables y permiten ordenar mejor la carga mensual.
  • Ambos módulos tienen CRUD funcional: crear, editar, activar/desactivar y eliminar protegido cuando corresponde.
  • Si una unidad o categoría ya está en uso, normalmente conviene desactivarla en vez de eliminarla.

Importación Excel

  • Permite carga masiva de compromisos y, según configuración, también pagos reales.
  • Primero se genera una vista previa antes de confirmar la importación.
  • La importación identifica y normaliza el modo del compromiso como CUOTAS, UNICO o RECURRENTE.
  • En compromisos en cuotas, el avance histórico se representa por cuotas restantes; por eso la importación evita crear PagoReal automático para no duplicar el descuento lógico.
  • La vista previa puede mostrar el estado "No crear (cuotas)" cuando una fila trae pagado pero corresponde a un compromiso en cuotas.
  • Existe historial de importaciones y opción de reversión cuando corresponde. La reversión se bloquea si detecta conciliaciones o trabajo posterior relevante.
  • Conviene respetar siempre la plantilla oficial para evitar errores de estructura o formato.
  • Si el archivo histórico viejo ya trae gastos mensuales cargados como registros puntuales, no es obligatorio convertirlos todos de inmediato al esquema recurrente.

Cartolas y conciliación bancaria

  • Sirve para trabajar movimientos bancarios importados y relacionarlos con pagos reales registrados.
  • Ayuda a validar si lo que salió del banco coincide con lo que se registró en el sistema.
  • Incluye conciliación, desconciliación y flujos de sugerencias / auto-conciliación.
  • Es un bloque de control complementario, no el centro de la gestión diaria.

Auditoría del sistema

  • Registra acciones críticas y cambios relevantes realizados por los usuarios.
  • Permite revisar quién hizo un cambio, cuándo lo hizo y qué cambió.
  • Incluye filtros por búsqueda, acción, módulo, modelo, usuario y rango de fechas.
  • La vista abre con los registros más recientes y el botón Limpiar deja los filtros realmente vacíos.
  • Es especialmente útil para revisar ediciones, eliminaciones, pagos, parametrización, importaciones y conciliaciones.
  • No reemplaza el trabajo operativo: su objetivo es aportar trazabilidad y control interno.
Uso recomendado: si aparece una inconsistencia o necesitas confirmar una modificación, revisa Auditoría antes de intervenir nuevamente los datos.

Empresa

  • Guarda los datos institucionales básicos de la empresa única actual.
  • Esta sección no es multiempresa: es una configuración base para la instalación actual.
  • El logo y nombre de empresa ayudan a dar identidad visual al sistema.
  • Estos datos pueden reutilizarse luego en reportes, exportaciones o documentación institucional.

Buenas prácticas de uso

  • No dupliques compromisos: si ya existe uno vigente, revisa si corresponde editarlo o registrar un pago real.
  • Usa anular antes que eliminar, salvo casos muy claros donde sí corresponda eliminación definitiva.
  • Para gastos mensuales permanentes, prefiere recurrente mensual.
  • Antes de confirmar una importación, revisa siempre la vista previa.
  • Usa filtros en cuentas por pagar y reportes para trabajar con vistas más limpias y precisas.
  • En reportes, distingue siempre entre histórico pagado y proyección futura: responden preguntas distintas.
  • Aprovecha los Reportes rápidos cuando quieras responder una pregunta de gestión frecuente sin reconstruir filtros manualmente.
  • Si necesitas rastrear un cambio, consulta el módulo de auditoría antes de corregir manualmente.
